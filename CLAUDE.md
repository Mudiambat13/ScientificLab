# ScientificLab - guidance for Claude Code

Open-source Python 3.11+ scientific library (MIT). `src/scientificlab/` layout.

## Commands

```bash
pip install -e ".[dev]"
pytest
ruff check . && ruff format --check .
mypy
```

## Principles

- Scientific accuracy over quantity of features. Never return an inconsistent
  result without signalling it (raise an explicit exception).
- No fake features, no empty functions to fill the architecture. Planned
  subpackages only contain a docstring until their phase.
- Every feature: real calculation + tests with known reference values.
- Separate validation (`utils/validation.py`), computation, and display.
- Do not confuse symbolic and numerical results; document which is returned.
- Document units, sign conventions, validity domains and tolerances.
- Keep dependencies minimal; add a library only in the phase that uses it.
- Never delete existing files without justification. Update README and
  CHANGELOG at each important step.
- Core physics functions use plain floats in SI units; `units.physics` offers
  Pint-aware wrappers. Solver results must keep honest `exact/complete/verified` flags.
- The GUI serves SymPy-parsed text (eval): keep it loopback-only with token and
  Host/Origin checks; never relax them.
- README images live in `docs/assets/` and are regenerated by
  `scripts/make_readme_figures.py`; keep paths relative (rewritten for PyPI at build).
- Docs are written in English (examples may add French explanations).

## Phases

1 Foundation (done) | 2 Mathematics core (done) | 3 Physics core (done) | 4 Scientific tools (done)
| 5 Simulations (done) | 6 Publication (done) | 0.7 statistics (done). Do not start a phase before the previous one
passes its tests, lint and type checks. End each phase with: files created,
features, tests run, results, problems, next steps.
